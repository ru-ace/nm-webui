# Техническое задание (ТЗ): Сервис управления NetworkManager (nm-webui)

## 1. Общие сведения
* **Наименование проекта:** `nm-webui` (NetworkManager Web Interface).
* **Целевая платформа:** Linux (ARM64 / RK3568, x86_64), ОС Armbian / Debian.
* **Назначение:** Автономный легковесный сервис для конфигурирования сетевой подсистемы через NetworkManager по протоколу HTTP(S) с упором на сценарии тревел-роутера (быстрое подключение к Wi-Fi гостиниц с мобильных устройств) и общее администрирование интерфейсов.

---

## 2. Архитектура и стек технологий

```text
┌──────────────────────────────────────────────────────────────┐
│                    nm-webui (Single Binary)                  │
│                                                              │
│  ┌─────────────────────────┐      ┌───────────────────────┐  │
│  │   Embedded Web SPA      │      │    Go HTTP Server     │  │
│  │   (Svelte/Vue + Tailw.) │ <──> │    (chi router, SSE)  │  │
│  └─────────────────────────┘      └───────────┬───────────┘  │
│                                               │              │
│                                   ┌───────────▼───────────┐  │
│                                   │   D-Bus Client        │  │
│                                   │   (godbus / libnm)    │  │
│                                   └───────────┬───────────┘  │
└───────────────────────────────────────────────┼──────────────┘
                                                │ System D-Bus
                                                ▼
                         ┌─────────────────────────────┐
                         │  NetworkManager.service     │
                         └─────────────────────────────┘
```

* **Язык разработки бэкенда:** Go (1.22+).
* **Сетевой стек D-Bus:** `github.com/godbus/dbus/v5` или обертка `github.com/Wifx/gonetworkmanager`. Прямое взаимодействие с шиной `org.freedesktop.NetworkManager` без вызова сторонних CLI-утилит (`nmcli`, `ip`).
* **Роутинг и API:** `net/http` + `github.com/go-chi/chi/v5`.
* **Фронтенд:** Svelte (или Vue 3) + Vite + Tailwind CSS + DaisyUI / Lucide Icons.
* **Формат поставки:** Единый статически скомпилированный бинарный файл (`go:embed` для статики фронтенда).

## 3. Функциональные требования

### 3.1. Модуль Wi-Fi (Приоритетный сценарий)
1. **Сканирование эфира:**
   * Отправка запроса на принудительное сканирование (`RequestScan`).
   * Отображение списка найденных сетей: SSID, BSSID, уровень сигнала (RSSI / процент), частота/канал (2.4 GHz / 5 GHz), тип шифрования (Open, WPA2-PSK, WPA3-SAE, Enterprise).
   * Сортировка по уровню сигнала.
2. **Подключение к сети:**
   * Подключение к открытым сетям без пароля (для отелей с Captive Portal).
   * Подключение к защищенным сетям с вводом пароля (PSK).
   * Индикация процесса (Scanning → Associating → Configuring IP → Connected / Error).
3. **Управление известными сетями:**
   * Просмотр сохраненных профилей Wi-Fi.
   * Возможность «Забыть сеть» (удаление профиля из NM).
   * Включение/отключение автоподключения (`autoconnect`).

### 3.2. Модуль интерфейсов и IP-адресации (L2 / L3)
1. **Список сетевых адаптеров:**
   * Тип устройства (Ethernet, Wi-Fi, Bridge, Loopback).
   * MAC-адрес, текущий MTU, состояние линка (Carrier Up/Down).
   * Текущие назначенные IPv4 / IPv6 адреса, шлюз по умолчанию (Gateway), список DNS-серверов.
2. **Конфигурация интерфейса (профиля):**
   * Переключение режима IPv4: `DHCP (Auto)`, `Manual (Static IP, Netmask, Gateway, DNS)`, `Disabled`.
   * Возможность поднять / положить интерфейс (Connect / Disconnect).

### 3.3. Модуль Dashboard (Сводка)
* Общий статус сетевого подключения: `Online / Limited / Offline` (на основе свойства NM `Connectivity`).
* Внешний/шлюзовой IP-адрес.
* Быстрый переключатель основного Wi-Fi клиента (Connect / Disconnect).

### 3.4. Авторизация и безопасность
* Защита веб-панели по единому паролю администратора (Session Cookie или Bearer JWT / Basic Auth).
* Возможность смены пароля администратора через конфигурационный файл или переменные окружения.

## 4. Спецификация API (REST + SSE)

Базовый путь: `/api/v1`

### 4.1. Общие данные и устройства
* `GET /api/v1/system/status` — общий статус интернета (online/offline), имя хоста, версия NM.
* `GET /api/v1/devices` — список всех сетевых устройств с их параметрами.
* `GET /api/v1/devices/{iface}` — детальная информация по конкретному интерфейсу.
* `POST /api/v1/devices/{iface}/disconnect` — деактивация интерфейса.

### 4.2. Беспроводные сети
* `POST /api/v1/wifi/{iface}/scan` — инициировать сканирование (NM `RequestScan`).
* `GET /api/v1/wifi/{iface}/networks` — получить список найденных AP (SSID, Signal, Security, Channel).
* `POST /api/v1/wifi/{iface}/connect` — подключиться к сети.
  * *Тело запроса:* `{"ssid": "Hotel_WiFi", "password": "optional_pass"}`.
  * *Ответ:* Статус постановки задачи или результат создания/активации профиля.

### 4.3. Сохраненные соединения (Settings)
* `GET /api/v1/connections` — список профилей в системе.
* `POST /api/v1/connections` — создание/изменение профиля (настройка статического IP или DHCP).
* `DELETE /api/v1/connections/{uuid}` — удаление профиля.
* `POST /api/v1/connections/{uuid}/up` — принудительная активация профиля на совместимом девайсе.

### 4.4. Потоковые события (Real-time)
* `GET /api/v1/events` (Server-Sent Events, `text/event-stream`):
  * Трансляция сигналов D-Bus:
    * `device_state_changed` — подключен/отключен кабель, получен IP.
    * `scan_done` — завершено сканирование Wi-Fi.
    * `connectivity_changed` — изменился глобальный статус доступа в сеть.

## 5. Требования к интерфейсу (UI/UX)

1. **Mobile-First дизайн:**
   * Интерфейс должен быть оптимизирован под мобильные экраны (смартфон в вертикальной ориентации — основной инструмент настройки тревел-роутера).
   * Крупные кнопки для выбора сетей, удобная экранная клавиатура для ввода паролей.
2. **Отзывчивость (UX):**
   * Сканирование сетей не должно блокировать интерфейс.
   * Визуальный индикатор (спиннер / skeleton loader) на время ожидания ответа от DHCP/Wi-Fi ассоциации.
3. **Локализация:** Английский язык (как базовый), поддержка русского опционально.

## 7. Конфигурация и запуск

Сервис должен конфигурироваться через CLI-флаги или файл `config.yaml` / ENV-переменные:
* `--listen`: IP и порт (по умолчанию `:8080` или `0.0.0.0:8080`).
* `--auth-pass`: пароль для входа в веб-интерфейс (если не задан — режим без пароля).
* `--interface-filter`: список интерфейсов для отображения (например, исключить Docker/veth/virbr интерфейсы, оставив только физические).

### Systemd Unit (`/etc/systemd/system/nm-webui.service`)
```ini
[Unit]
Description=NetworkManager Web UI
After=network.target NetworkManager.service
Wants=NetworkManager.service

[Service]
Type=simple
ExecStart=/usr/local/bin/nm-webui --listen 0.0.0.0:8080 --auth-pass "SecretAdminPass"
Restart=always
RestartSec=5
User=root
# Либо запуск от отдельного пользователя с правами доступа к D-Bus политике netdev

[Install]
WantedBy=multi-user.target
```

## 8. Этапы реализации

* **Этап 1 (PoC D-Bus & Core):** Написание Go-демона, подключение к System D-Bus, чтение списка устройств и сканирование Wi-Fi через API `org.freedesktop.NetworkManager`.
* **Этап 2 (REST API & Connect):** Реализация логики создания профиля подключения к Wi-Fi и получение IP по DHCP. Обработка ошибок авторизации (неверный пароль / timeout).
* **Этап 3 (Frontend Base):** Верстка мобильного SPA: экран списка сетей, модальное окно пароля, экран текущего состояния адаптеров.
* **Этап 4 (SSE & Реактивность):** Проброс D-Bus сигналов в браузер через Server-Sent Events для «живого» обновления статуса подключения.
* **Этап 5 (L3 и профили):** Добавление функционала настройки статического IP/DHCP для проводных интерфейсов.
* **Этап 6 (Сборка и упаковка):** Вшивание фронтенда через `embed.FS`, кросс-компиляция под `linux/arm64`, создание deb-пакета или простого установочного скрипта.
* **Этап 7 (Документирование ):** Создание README.md на русском и английском, а также INSTALL.md на русском и английском c инструкцией для ручной сборки с указанием необходимых пакетов  и команд.
